# connector-whatsapp — מספר קורא (Reader)

שירות Node.js קטן שמחזיק את חיבור הוואטסאפ בפועל, דרך הספרייה הלא-רשמית
[Baileys](https://github.com/WhiskeySockets/Baileys) (פרוטוקול Multi-Device,
כמו WhatsApp Web). זהו **המספר הקורא בלבד** — הוא לא שולח הודעות לקבוצה,
למעט הודעת גילוי חד-פעמית. ראו סעיף 10.2 במסמך האפיון להסבר המלא על
ההחלטה הארכיטקטונית ההיברידית (קורא לא-רשמי + שולח רשמי).

## הרצה
```bash
cd connector-whatsapp
npm install
npm start
```

יש שתי דרכים להתחבר בהרצה הראשונה:

**אופציה א' — קוד צימוד (מומלץ, בלי QR):** מלאו את `READER_WHATSAPP_NUMBER`
ב-`.env` הראשי (בפורמט בינלאומי, לדוגמה `+972501234567`) *לפני* ההרצה.
כ-3 שניות אחרי שהשירות עולה יוצג בטרמינל קוד בן כמה ספרות/אותיות. הזינו
אותו בטלפון שבו רוצים להשתמש כמספר הקורא: וואטסאפ ‹ הגדרות ‹ מכשירים
מקושרים ‹ קישור מכשיר ‹ "קישור עם מספר טלפון במקום".

**אופציה ב' — סריקת QR (ברירת המחדל אם `READER_WHATSAPP_NUMBER` ריק):**
יוצג קוד QR בטרמינל. סרקו אותו מהטלפון שבו רוצים להשתמש (וואטסאפ ‹ מכשירים
מקושרים ‹ קישור מכשיר).

בשני המקרים: פרטי החיבור (session) נשמרים בתיקיית `auth/` (לא נכנסת ל-git)
ולכן זה קורה פעם אחת בלבד — אין למחוק אותה אלא אם רוצים לאתחל את החיבור
מחדש (למשל כדי לעבור למספר אחר).

## איך זה עובד
1. משתמש קצה משלים את אשף ההרשמה (`/onboarding`) בליבה — זה יוצר את החשבון שלו.
2. הוסיפו את מספר ה-Reader לקבוצת הוואטסאפ שרוצים לנטר עבור אותו משתמש.
3. **אין צורך למצוא/להזין את מזהה הקבוצה (JID) ידנית**: הליבה מזהה וקושרת
   אוטומטית את הקבוצה לחשבון הנכון מההודעה הראשונה שמגיעה ממנה, לפי סדר
   ההרשמה (Multi-tenant — ראו `MONITORED_GROUP_ID` ב-`.env.example` והסבר
   מלא ב-README הראשי). מספר Reader אחד יכול להיות חבר בכמה קבוצות בו-זמנית,
   אחת לכל משתמש רשום.
4. כל הודעה/סטיקר/תמונה/אירוע קבוצה מנורמלים ונשלחים ב-HTTP POST לשירות
   הליבה (`CORE_SERVICE_URL/webhooks/whatsapp/reader`), מאומת בכותרת
   `X-Connector-Secret` מול `CONNECTOR_SHARED_SECRET`.

## ניטור רק מרגע הצירוף — לא הודעות היסטוריות
המערכת בנויה כך שהיא **אינה** מנתחת/קוראת הודעות שנשלחו בקבוצה לפני
שמספר ה-Reader הצטרף אליה, בכמה שכבות הגנה שכל אחת מהן עצמאית ומספיקה בפני עצמה:
1. הקוד כלל לא מאזין לאירוע `messaging-history.set` של Baileys (מנגנון
   סנכרון ההיסטוריה של WhatsApp Multi-Device) — כך שגם אם WhatsApp מנסה
   לשלוח היסטוריה, אנחנו פשוט לא קוראים אותה.
2. באירוע `messages.upsert` מסוננות במפורש רק הודעות מסוג `notify` (הודעות
   חיות בזמן אמת) — הודעות מסוג `append` (backfill היסטורי) נזרקות (ראו
   `sock.ev.on("messages.upsert", ...)` ב-`index.js`).
3. הגנה נוספת (defense-in-depth): כל הודעה נבדקת מול `MAX_MESSAGE_AGE_SECONDS`
   (ברירת מחדל 300 שניות/5 דק') — הודעה עם חותמת זמן ישנה מזה נזרקת ונרשמת
   ביומן, גם אם משום מה הגיעה מסומנת כ-`notify`.
4. בצד הליבה (Python): הודעות המגיעות **לפני** שמשתמש סיים את אשף ההרשמה
   נדחות ולא נשמרות כלל (`ignored_no_account`) — כך שגם תקופת ביניים לפני
   שהחשבון נוצר לא נכנסת למערכת.
5. וואטסאפ עצמו, כעניין פרוטוקולרי, אינו משתף הודעות שנשלחו בקבוצה לפני
   שחבר הצטרף אליה — אף לקוח (כולל WhatsApp Web/Multi-Device) לא מקבל
   גישה רטרואקטיבית להיסטוריית קבוצה מלפני ההצטרפות.

## סיכון חשוב
שימוש בספריה לא-רשמית מנוגד לתנאי השימוש של וואטסאפ, ויש סיכון לחסימת
המספר. לצורך POC על קבוצה אחת זהו הסיכון המחושב שהוחלט עליו במסמך האפיון
(סעיף 10.2). מומלץ להשתמש במספר וירטואלי ייעודי ל"חימום" ולא במספר אישי.
